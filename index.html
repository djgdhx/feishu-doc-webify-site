  • 两枚是同一代模块的新旧两版固件，底层均为 EG25GGBR07A08M2G（V07 / Qualcomm）。

三、电话与音频链路原理

3.1 USB Audio Class（UAC）

东西Windows 里看到什么用途
EG25-G AT 接口COM3 / COM4 / COM5…拨号、接听、挂断
EG25-G UACQuectel USB Audio / USB Audio Device电话声音
电脑麦克风Microphone你讲话
电脑耳机/音箱Speakers / Headphones你听对方
  • EG25-G 开启 UAC 后，Linux / Windows 会把它识别为一个 USB 音频设备。
  • 可以理解为：EG25-G 是“手机本体”，USB UAC 是“数字耳机线”。
  • 对方声音：运营商 → EG25-G → USB → 系统。
  • 你的声音：系统 → USB → EG25-G → 运营商。

3.2 实际数据流

方向流程
对方说话 → 你听到手机网络 → EG25-G → UAC → ALSA → Asterisk → SIP App
你讲话 → 对方听到SIP App → Asterisk → ALSA → UAC → EG25-G → 手机网络

3.3 Linux ALSA / Asterisk / SIP

名称全称最简单理解在你的项目里的作用
EG25-GQuectel LTE Modem没有屏幕的手机插 SIM 卡，连接运营商，负责打电话
AT CommandAttention Command控制手机的指令告诉 EG25-G：拨号、接听、挂断
UACUSB Audio ClassUSB 声卡把通话声音从 EG25-G 传到 Linux
ALSAAdvanced Linux Sound ArchitectureLinux 声音管理系统让 Linux 识别和处理 UAC 音频
Asterisk开源电话交换机软件电话总机管理电话、转接、连接 SIP
SIPSession Initiation Protocol网络电话协议让手机 App 通过网络接入电话
  • Linux ALSA：Linux 管理声音设备的系统。
  • Asterisk：Linux 上的电话交换机软件，负责呼叫转接、录音、SIP 账号、电话规则。
  • SIP：网络电话协议；常见客户端有 Zoiper、Linphone、Acrobits。
  • 目标链路：SIM → EG25-G → UAC → Linux ALSA → Asterisk → SIP 电话。

3.4 能拨、能接、能挂，但听不见

条件是否必须
SIM 套餐支持语音✅
运营商允许该 SIM 使用 VoLTE/语音✅
模块注册到 IMS/VoLTE 或可用语音网络✅
固件支持语音呼叫✅
想真正听说话，还要 UAC/PCM✅
  • 只用 ATD / ATA / ATH 控制电话时，电话确实接通，但没有音频链路时听不见、也说不了话。
  • 需要再接 UAC / PCM 音频链路，才能实现双向语音。
  • 开发顺序建议：先做电话控制 UI，再接入 UAC 音频。

3.5 UAC 打开以后会发生什么

USB功能相当于
COM AT Port控制线
QMI/网络接口网卡
UAC Audio声卡
  • Windows 会多识别一个类似 Quectel USB Audio 的设备。
  • 进入“设置 → 系统 → 声音”，可以看到新的音频输入 / 输出设备。
  • EG25-G 在同一个 USB 口上同时提供多个接口。

3.6 容易误解的地方：必须做音频桥接

  • 电话接通后，Windows 不会自动把电脑麦克风送给 EG25-G。
  • 需要音频桥接：电脑麦克风 → 音频桥接软件 → EG25-G UAC；反方向同理。
  • 实验阶段可用 VoiceMeeter、Virtual Audio Cable、FFmpeg 或自己写小程序。
  • 做正式产品时，应由程序自动完成桥接。

3.7 最直观的使用方式

操作怎么做
拨号在 AT 串口执行 ATD号码;
接电话执行 ATA
挂电话执行 ATH
听对方EG25 UAC → Windows → 耳机
对方听你耳机麦克风 → Windows → EG25 UAC
  • Windows PC + EG25-G + USB 转接板 + 带麦克风耳机。
  • 人只需戴电脑耳麦讲话，和正常电脑语音聊天差不多。
  • 完全不用跑到模块旁边对着模块说话。

3.8 为什么最终推荐 Linux

Windows实验Linux成品
串口工具手动 AT程序自动控制 AT
VoiceMeeter 搬声音ALSA 自动处理声音
人坐电脑前接电话Asterisk 自动接入
本机耳麦SIP / WebRTC 远程
适合测试适合做你的盒子
  • 不是因为 Windows 做不到，而是后续要做 VoHive + Web UI + 远程接电话 + SIP，Linux 更方便。
  • 远程架构：设备放在悉尼，人在上海，手机 App / 浏览器连回 Linux 盒子。
  • UAC 只解决“EG25-G ↔ 电脑”这一段声音；人在哪里讲话由后面软件决定。

4.4 首次上电会自动做什么

  • 电脑负责供电和提供 USB 通道，EG25-G 自己启动、读 SIM、搜网、注册网络。
  • 上电流程：上电 → 检测 SIM → 搜索网络 → 尝试注册。
  • AT+CSQ 是问信号；AT+COPS? 是问运营商；AT+QNWINFO 是问网络和频段。

4.5 供电注意事项

  • 不一定所有转接板都只靠电脑 USB 供电。
  • 有些板带 DC 电源口、额外 5V 输入或独立供电接口。
  • 蜂窝模块发射瞬时电流较高，供电不稳会出现重启、掉线、USB 消失等问题。
  • 只要插 USB 后能稳定启动、能看到 COM 口且不反复断开，说明供电基本够用。

4.6 WSL2 与原生 Linux

Windows 11 里的“Linux”能不能拿来接 EG25-G结论
WSL / WSL2⚠️ 可以折腾，但 USB 直通麻烦不推荐你第一步就用
Hyper-V 虚拟机里的 Ubuntu⚠️ USB 直通也麻烦不推荐
VMware / VirtualBox Ubuntu✅ 可做 USB 直通可以
双系统 Ubuntu✅ 原生识别 USB很适合
独立 Linux 小主机 / 树莓派✅ 最稳定最推荐
阶段推荐做法
先验证模块Windows 11 直接用 COM 口发 AT 命令
真正跑 VoHive独立 Linux / 树莓派 / Ubuntu 双系统
  • Windows 11 的 Linux 环境能否跑 VoHive，取决于是不是 WSL2。
  • WSL2 里 EG25-G 的 COM 口、QMI / wwan0、UAC 声卡默认不会全部直接出现。
  • 需要 USB passthrough（如 usbipd-win），比直接装 Linux 麻烦。
  • 建议先 Windows 验证“识别、拨号、接听”，再迁移到原生 Linux 跑 VoHive。
